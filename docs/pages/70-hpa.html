{{ page_head("Scale a workload with its load") }} {% call stage("understand") %} {{ section("idea", "The idea") }}

A HorizontalPodAutoscaler (HPA) changes how many pods a workload runs, to keep a metric, such as their CPU, near a target. When the new pods do not fit on the nodes, EKS Auto Mode adds a node.

For the HPA to scale a workload, the Rollout leaves out replicas, and an HPA points at it.

{% include "partials/70-hpa/owner.html" %} {{ section("how", "How the HPA scales") }}

The pods and the nodes follow the load: the HPA changes the pods, and Auto Mode changes the nodes.

{% include "partials/70-hpa/scaling.html" %} {{ section("count", "How the HPA counts pods") }}

The HPA looks at utilization: the CPU that a pod uses, as a share of the CPU that the pod requests. When the average utilization rises above the target, the HPA adds pods, so that the CPU in use spreads over more pods and the average comes back to the target.
